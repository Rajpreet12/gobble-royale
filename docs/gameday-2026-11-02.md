# Game day: 2026-11-02

**Goal:** prove, before Thanksgiving, that a real outage is detected, paged, fixed with the runbook, and cleared, and find anything that doesn't work while it's cheap to find.

**Run by:** Rajpreet (with Claude Code driving the commands) · **Where:** production, `gobble-royale` Lightsail server

## Safety

| | |
|---|---|
| **When** | A quiet weekday morning, weeks before launch |
| **Go / no-go** | Go only if **0 players online** and **error budget above 90%** |
| **Blast radius** | The live game is down for about 8 minutes. The uptime checker, alerts and error budget are separate and keep working. Scores are saved before the stop, so nothing is lost. |
| **Budget cost** | About 8 to 10 bad minutes of 216 (around 4%). The policy allows this above 50%: spending budget on learning is what it's for. |
| **Abort if** | A real player joins, the game doesn't come back with `systemctl start gobble`, or anything unexpected breaks. Abort = `sudo systemctl restart gobble caddy` and stop the experiment. |

## Experiment 1: the game crashes

- **Do:** `sudo kill -9` the game process. That's a hard crash, with no chance to clean up.
- **Hypothesis:** systemd restarts it within about 2 seconds (`Restart=always`, `RestartSec=2`). The uptime checker fails at most once, passes on its 2-second retry, and records a good minute. **No page.**
- **Measure:** `NRestarts` goes up by 1, no bad minute is recorded, no email.

## Experiment 2: the game is down for real

- **Do:** `sudo systemctl stop gobble`. The process stays down, the way it would after a crash systemd can't recover from, or a bad deploy.
- **Hypotheses:**
  1. The first bad minute is recorded within about 1 minute.
  2. A **[PAGE]** email is sent at the **5th bad minute** (burn rate 16.7×, over the 14.4× threshold), about 5 minutes in.
  3. Following the PAGE runbook section (check → `systemctl restart gobble`) brings the game back.
  4. A **[RESOLVED]** email arrives after 5 clean minutes.
  5. Exactly 2 emails, no slow-burn ticket (inhibition).
- **Measure:** time to detect, time to page, time to recover, budget spent, emails received.
